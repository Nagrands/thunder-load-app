# Вкладка «Плеер»

Документ описывает пользовательские сценарии, архитектуру, данные, IPC и
платформенные интеграции Плеера. Описание соответствует состоянию приложения
после миграции медиатеки на версию 3.

## Возможности

- локальные аудио- и видеофайлы;
- папки с поддерживаемыми медиафайлами;
- одиночные YouTube-видео с выбором качества;
- сетевые HTTP(S)-медиа и HLS из M3U/M3U8;
- пользовательские плейлисты и отдельная временная очередь;
- фоновое и полноэкранное воспроизведение;
- системные медиакнопки и системные метаданные;
- открытие файлов из Finder/Explorer и файловые ассоциации.

## Медиатека

Медиатека оформлена как плотный desktop media hub: компактная command bar
объединяет импорт и создание плейлиста, слева расположен узкий rail плейлистов
и отдельная временная очередь, а основной каталог остаётся list-first и
рассчитан на длинные имена. Медиатека доступна и без файлов: пустое состояние
показывается внутри области контента и не перекрывает навигацию или импорт.

Из пустого состояния можно:

- добавить файлы;
- добавить папку;
- добавить YouTube-ссылку;
- создать плейлист.

Локальный поиск работает по названию, исполнителю и альбому активного
плейлиста. Фильтры «Все / Видео / Аудио / Недоступные» применяются поверх
поиска, сохраняются только до закрытия renderer-сессии и не меняют state v3.
Если элементы есть, но не подходят запросу, выводится отдельное no-results
состояние.

Строка медиа содержит обложку или fallback, отображаемое название, исполнителя
и альбом, доступные badges разрешения и кодеков, длительность, размер, состояние
доступности и кнопку контекстного меню. Неизвестные технические поля скрываются.
Переименование меняет только `displayTitle` в медиатеке. Удаление исключает
запись из каталога и плейлистов, но не удаляет и не переименовывает физический
файл.

Нижний mini-player — центрированный glass-dock с тремя симметричными зонами:
идентичность медиа, Previous/Play/Next с timeline и громкость с возвратом в
полный Player. На компактной ширине вторичные metadata и volume скрываются
раньше основных transport-команд.

### Контекстное меню

Меню открывается кнопкой строки, правой кнопкой мыши, клавишей `ContextMenu` или
`Shift+F10`. Поддерживаются стрелки, `Home`, `End`, `Escape` и восстановление
фокуса.

Действия:

- воспроизвести;
- добавить во временную очередь;
- добавить в пользовательский плейлист;
- переместить выше или ниже в пользовательском плейлисте;
- показать в Finder/Explorer;
- открыть содержащую папку;
- показать информацию;
- изменить отображаемое название;
- удалить из медиатеки или активного плейлиста.

Файловые действия скрыты для YouTube и сетевых элементов. Для отсутствующего
локального файла воспроизведение и файловые действия отключены.

## Плейлисты и временная очередь

Пользовательские плейлисты сохраняются вместе с медиатекой. Их можно создавать,
переименовывать, удалять и менять порядок элементов. Системный плейлист
«Медиатека» содержит весь каталог и не удаляется.

Временная очередь «Далее» хранится только в памяти:

- элементы, добавленные вручную, воспроизводятся раньше продолжения активного
  плейлиста;
- очередь можно просматривать, менять её порядок, очищать и удалять отдельные
  элементы;
- очередь не попадает в состояние v3 и очищается после перезапуска.

Если Finder или Explorer передаёт несколько файлов, первый импортируется и
запускается, остальные помещаются во временную очередь.

### Окна Плеера

Создание и переименование плейлиста, добавление YouTube-ссылки, выбор качества,
добавление трека в плейлист, изменение отображаемого названия и информация о
треке используют общий шаблон модального окна Thunder. Окна поддерживают
закрытие по `Escape`, клику по затемнению, крестику и кнопке отмены, удерживают
фокус внутри и возвращают его вызвавшему элементу.

YouTube-окно не закрывается между анализом URL и выбором качества. Во время
анализа форма показывает busy-состояние, а ошибка выводится внутри окна без
потери введённой ссылки. Удаление плейлиста и записи медиатеки по-прежнему
требует подтверждения в общем confirmation modal.

## Элементы воспроизведения

Dock и надпись «Сейчас играет» видимы во время подготовки, воспроизведения и
паузы. Они скрываются после Stop, окончания очереди или при отсутствии трека.
Переход использует `opacity`, `transform` и `max-height`; после завершения
скрытия dock становится `inert`. При `prefers-reduced-motion: reduce` переходы
отключаются.

Повтор переключается циклом:

1. выключен;
2. текущий файл (`1`);
3. весь плейлист;
4. выключен.

Процент громкости появляется при изменении, прокрутке, mute, hover или focus и
скрывается через 1500 мс. Ползунок остаётся видимым. Кнопки dock, mini-player и
строк используют общий `tooltipInitializer.js`; динамические подписи
Play/Pause/Repeat обновляются вместе с `aria-label`.

Нижний mini-player медиатеки разделён на три зоны: обложка и метаданные,
transport controls с временной шкалой, громкость и переход в полный Плеер.
Текстовая кнопка «Сейчас играет» заменена компактной кнопкой-иконкой. На узком
окне сначала скрываются альбом и ползунок громкости, затем временная шкала
переходит на вторую строку; Previous, Play/Pause, Next и переход в полный Плеер
остаются доступны.

## YouTube и выбор качества

Добавление YouTube-видео выполняется в два этапа:

1. main process получает полные метаданные и форматы через `yt-dlp`;
2. пользователь выбирает `Auto`, `Best`, `Audio` или конкретный формат.

Для форматов показываются доступные разрешение, FPS, контейнер, video/audio
codec, bitrate и приблизительный размер. Конкретный выбор сохраняет стабильные
`format_id` или пару video/audio `format_id`, а не временный media URL.

Если сохранённый формат больше недоступен, Плеер возвращает
`YOUTUBE_QUALITY_UNAVAILABLE`. Автоматического незаметного перехода на `Auto`
нет; пользователь может повторить выбор или выполнить явный retry.

Все YouTube-варианты воспроизводятся через локальный HLS-конвейер. Метаданные
кешируются на 5 минут (до 32 записей), playback selection — на 90 секунд (до
32 записей). Ключ воспроизведения включает URL и selector, а параллельные
resolve одного варианта дедуплицируются.

## Локальный HLS и FFmpeg

`src/js/app/nowPlayingHlsService.js` создаёт защищённую playback-сессию:

- HTTP-сервер слушает только случайный порт `127.0.0.1`;
- путь содержит криптографически случайный token и UUID сессии;
- принимаются только URL, разрешённые main process, или предварительно
  проверенный локальный путь;
- клиенту доступны только manifest и сегменты текущей сессии;
- H.264/AAC может использовать stream-copy, остальные кодеки транскодируются;
- для транскодирования сначала пробуется `-hwaccel auto`, затем CPU fallback;
- процессы завершаются при освобождении media layer, закрытии сессии и выходе;
- действует TTL 30 минут, максимум 8 сессий и общий лимит кэша 2 ГБ.

HLS воспроизводится через локальную зависимость `hls.js`. Поддерживаемые Chromium
локальные файлы открываются напрямую. AVI, MPEG и MPG направляются через
FFmpeg/HLS, поскольку их контейнеры и кодеки ненадёжно поддерживаются Chromium.

## Нативный выбор аудиодорожки

Для главного `BrowserWindow` включена Blink-функция `AudioVideoTracks`.
Совместимые локальные MP4, MKV и другие напрямую воспроизводимые контейнеры
переключают звук через `HTMLMediaElement.audioTracks`: источник, media layer,
playback-сессия, позиция и Play/Pause при этом не меняются. FFmpeg и HLS в
сценарии выбора дорожки не используются.

`ffprobe` возвращает не более 32 аудиопотоков и их порядок. Выбор разрешается,
только если количество и порядок нативных дорожек Chromium совпадают с
результатом анализа. «Автоматически» включает помеченную default-дорожку или
первую. При ошибке setter восстанавливаются прежние флаги `enabled`, а состояние
v3 обновляется только после успеха.

AVI, MPEG, MPG, YouTube, сетевые источники, отсутствующий `AudioTrackList`,
единственная дорожка и любое несовпадение списка показываются как
неподдерживаемые. Медленный FFmpeg fallback для переключения отсутствует.

## Форматы и M3U

Поддерживаемые расширения:

- аудио: `mp3`, `m4a`, `aac`, `flac`, `wav`, `ogg`, `opus`;
- видео: `mp4`, `mkv`, `webm`, `mov`, `avi`, `mpeg`, `mpg`;
- плейлисты: `m3u`, `m3u8`.

Импорт дополнительно понимает совместимые расширения `oga`, `weba` и `m4v`;
системные ассоциации регистрируют пользовательский набор из `package.json`.

Импорт M3U/M3U8:

- читает UTF-8 и удаляет BOM;
- игнорирует пустые строки, комментарии и вложенные плейлисты;
- разрешает относительные пути от каталога файла плейлиста;
- принимает поддерживаемые HTTP(S)-медиа и удалённый HLS;
- удаляет дубликаты;
- ограничен 1 МиБ и 1000 элементами;
- пропускает YouTube-ссылки с предупреждением, потому что для них нужен
  интерактивный выбор качества.

## Состояние v3

Сохраняются каталог, пользовательские плейлисты, активный плейлист, выбранный
трек, громкость, mute, shuffle, repeat и настройки фонового воспроизведения.

Track v3 включает:

- `id`, `providerId`, `sourceRef`;
- `title`, `displayTitle`, `artist`, `album`;
- `duration`, `sizeBytes`, `kind`, `mimeType`;
- `artworkUrl`, `availability`, `qualitySelection`, `selectedAudioTrackId`.

Поддерживаются провайдеры `local`, `youtube` и `network`. Состояния v1/v2
детерминированно нормализуются в v3. Временная очередь, HLS token, session ID и
истекающие URL не сохраняются.

`GET_STATE` обновляет доступность локальных файлов. `SET_STATE` только
валидирует и сохраняет данные и не выполняет полный `fs.stat` каталога.
Сохранение имеет trailing debounce 250 мс, single-flight и принудительный flush
при скрытии и dispose.

Защитные лимиты: до 5000 треков, 500 пользовательских плейлистов и 2 МиБ на IPC
payload сохраняемого состояния.

## Архитектура renderer

- `nowPlayingView.js` — orchestration и публичный lifecycle;
- `mediaLibraryModel.js` — каталог и плейлисты v3;
- `mediaLibraryView.js` — медиатека, empty state и mini-player;
- `playerDialog.js` — режимы и lifecycle общих модальных окон Плеера;
- `playbackController.js` — два media layer и transport state;
- `localMusicProvider.js`, `youtubeProvider.js`, `networkMediaProvider.js` —
  источники;
- `providerRegistry.js` — единый resolver и release lifecycle;
- `transientQueue.js` — неперсистентная очередь;
- `playerContextMenu.js` — доступное контекстное меню;
- `mediaSessionManager.js` — Chromium Media Session;
- `playbackControlsView.js`, `playlistRenderer.js` — точечные обновления UI;
- `fullscreenController.js` и `visualTransitionController.js` — экранный режим
  и визуальные переходы.

`renderer.js` только запускает регистрацию вкладок. Плеер создаётся лениво один
раз через `registerTabs.js` и сохраняется между переключениями вкладок.

## Архитектура main process и IPC

Main-модули:

- `nowPlayingState.js` — схема и миграция v3;
- `nowPlayingLibrary.js` — импорт, metadata, M3U и availability;
- `nowPlayingYouTube.js` — анализ качества, selector и resolve;
- `nowPlayingHlsService.js` — FFmpeg/HLS lifecycle;
- `nowPlayingTimelinePreviewService.js` — отменяемое извлечение и LRU кадров;
- `nowPlayingIpcHandlers.js` — валидация и structured results;
- `mediaOpenService.js` — startup argv, `second-instance` и macOS `open-file`;
- `window.js` — macOS Dock Menu snapshot и transport commands.

Новые каналы объявляются в `src/js/ipc/channels.js`, регистрируются через
`src/js/app/ipcHandlers.js` и явно разрешаются в whitelist `src/js/preload.js`.
Renderer не вызывает `ipcRenderer` напрямую.

Каналы Плеера:

| Направление             | Каналы                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Renderer → main, invoke | `now-playing:import-files`, `now-playing:import-folder`, `now-playing:import-paths`, `now-playing:analyze-youtube-video`, `now-playing:import-youtube-video`, `now-playing:resolve-youtube-track`, `now-playing:get-audio-tracks`, `now-playing:create-local-playback-session`, `now-playing:close-playback-session`, `now-playing:get-timeline-preview`, `now-playing:get-state`, `now-playing:set-state`, `now-playing:reveal-track`, `now-playing:open-track-location` |
| Renderer → main, send   | `now-playing:cancel-timeline-preview`, `now-playing:open-files-ready`, `now-playing:media-state`                                                                                                                                                                                                                                                                                                                                                                          |
| Main → renderer         | `now-playing:open-files`, `now-playing:media-command`                                                                                                                                                                                                                                                                                                                                                                                                                     |

Ошибки возвращаются в форме `{ success, data, error: { code, message } }`.

## Премиальный интерфейс и preview шкалы

Видео использует режим `contain`: кадр не обрезается, а свободное пространство
остаётся чёрным и перекрывается только мягкой виньеткой. Sidebar, верхний
toolbar и нижний dock являются отдельными glass-панелями, автоматически
скрываются во время воспроизведения и соблюдают настройки pin, low-effects и
`prefers-reduced-motion`.

Карточка текущего файла показывает доступные разрешение, video/audio codec и
размер. Эти данные находятся в необязательном `TrackV3.mediaInfo`; локальные
значения получает уже выполняемый при импорте `ffprobe`, YouTube — выбранные
форматы. Версия состояния остаётся v3.

Окно «Информация» использует отдельную presentation-карточку внутри общей
Player-модалки. Оно показывает artwork или временный timeline-poster,
название, artist/album, badges и доступные технические характеристики без
раскрытия полного локального пути или URL. Неизвестные значения скрываются;
для audio и отсутствующего artwork используется Lucide fallback. В режиме
информации остаётся одна кнопка «Закрыть», а остальные режимы общей формы
восстанавливают обычные поля и footer.

При наведении на шкалу renderer отправляет
`now-playing:get-timeline-preview`. Main process проверяет track/session,
округляет время до двухсекундного bucket и получает JPEG 320×180 отдельным
FFmpeg-процессом. Одновременно работает не более одного запроса; устаревшие
запросы отменяются через `now-playing:cancel-timeline-preview`, а результаты
хранятся в ограниченном LRU-кэше. Preview никогда не меняет `currentTime`
активного media element и не создаёт вторую playback-сессию.

Sidebar поддерживает double click для немедленного запуска и drag-and-drop
активного списка. Порядок пользовательского плейлиста или системной Медиатеки
сохраняется, а отдельная временная очередь «Далее» не изменяется.

## Производительность

- один lazy-created экземпляр Player;
- два переиспользуемых media layer для возврата `A → B → A`;
- `forceRefresh` инвалидирует reuse;
- position updates ограничены примерно 8 Гц;
- текст времени обновляется только при смене целой секунды;
- на tick обновляются только предыдущая, текущая и loading-строка;
- snapshot очереди не клонируется и полный каталог не обходится на каждом tick;
- media listeners сохраняются и снимаются при dispose;
- активная HLS-сессия освобождается вместе с media layer.

## Интеграция с операционной системой

Chromium Media Session является единым источником Now Playing Center на macOS,
SMTC на Windows и аппаратных media keys. Передаются название, исполнитель,
альбом, обложка, длительность, позиция и состояние. Поддерживаются Play, Pause,
Next, Previous, Stop и Seek.

Позиция Media Session публикуется не чаще одного раза в секунду, кроме смены
трека, состояния и явного seek. Аппаратное ускорение Electron остаётся
включённым по умолчанию; экспериментальные Chromium GPU flags не используются.

На macOS Dock Menu показывает текущий трек и команды Play/Pause, Previous и
Next. На Windows AUMID совпадает с `build.appId`: `com.thunderload.app`.

Ассоциации файлов объявлены в `package.json`. На macOS используются `Viewer` и
`Alternate`, поэтому Thunder доступен в «Открыть с помощью», но не захватывает
форматы автоматически. Windows NSIS использует `perMachine: true`, поэтому
установка требует elevation и регистрирует приложение для выбора по умолчанию.

## Проверка изменений

Минимальный набор:

```bash
npm run css:build
npm run whats-new:build
npm run lint
npm run typecheck:player
npm test
npm run check
```

При изменении Nunjucks дополнительно выполняется `npm run templates:build`.

Packaged QA выполняется отдельно на целевых системах:

- macOS x64/arm64: Now Playing Center, media keys, seek, Dock Menu, background,
  Open With;
- Windows: SMTC, media keys, metadata, per-machine NSIS, cold/warm OS-open;
- обе платформы: direct/HLS, очистка кэша и CPU/GPU/RAM.

Автоматические тесты не заменяют проверку системной панели, установщика и
ассоциаций на реальной целевой ОС.
